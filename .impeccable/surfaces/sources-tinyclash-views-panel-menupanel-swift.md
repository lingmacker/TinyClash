# Surface: TinyClash menu bar panel (the whole app)

Mode: Operate. Audience: the author, daily, on their own Mac. Jobs: toggle system proxy / TUN, switch mode and nodes, test latency, switch or update profiles, read currently loaded rules, adjust settings, and read live state. The user requested no main window ("直接把它完全变成一个菜单栏app 不需要主页面", "合理设计，保留核心功能"), then added "增加一个规则tab 显示当前的规则" and refined Rules by removing search and aligning each rule card in two clean rows. Constraints: native SwiftUI controls, follows system light/dark, Simplified Chinese, fixed 360×560 pt content. Sampled request routes are available within 策略; advanced connection controls, expanded rule-provider contents, provider details and core logs remain in metacubexd or the core log file.

## Direction contract

THESIS: The panel answers whether traffic is proxied, how, and through which primary group/node, before anything else. All everyday operations stay in a menu-bar popover, not a desktop window.

OWN-WORLD: Stash-inspired native macOS restraint: opaque cool-neutral canvas and rounded panels (14 pt), with no glass background, SF system text and rounded tabular numerals. Tabs, enabled tiles/mode segments, and emphasized buttons use pale apricot (`#FCE9DD`) with dark warm orange text (`#8C431C`); dark appearance adapts to muted warm brown (`#493429`) with soft apricot text (`#FFD3B7`). Small accents and native controls retain OrangePulse orange (`#F57B3F`), derived from `Resources/AppIcon.icon/Assets/03 OrangePulse.svg`; the brand mark pairs it with `#FF9661`. Semantic green/orange/red latency thresholds are 500/1000 ms; download is blue and upload teal.

STORY: Open the menu-bar icon, read proxy state and active profile, control system proxy/TUN and mode on 首页; open 策略 for group details, latency, node selection, 添加策略组, in-place group editing (context menu / detail header pencil, keeping name read-only and unmanaged YAML keys intact) and deleting groups (context menu / detail header / edit page), which validates and writes standard YAML directly to the selected file; use 配置 for subscriptions/YAML; use 规则 for the core's actual matching order, refresh, 添加规则, clicking rows for in-place editing (with header trash), and context-menu row deletion, with two-row cards keeping payload/type left-aligned and chevron/policy right-aligned, using the same direct-file pattern without any custom-item manager; edits to groups or rules defer core restart by switching the header status pill to a clickable orange 「需重启生效」 while keeping Proxies and Rules lists in sync with the edited YAML; use 设置 for system/core/data actions.

FIRST VIEWPORT: Header (app mark, active profile, explicit proxy state; live speeds off Home), five tabs (首页 策略 配置 规则 设置), then on 首页: two toggle tiles, mode segmented control, compact group→node route ribbon with latency, live traffic chart and four facts, three quick actions, and a fixed bottom footer with 配置文档 / 退出 TinyClash. The footer stays outside the scroll view with a 12 pt bottom inset instead of leaving unused space below Home's content. Compact routes omit a duplicate mode chip because the segmented picker already shows it. Proxy cards echo the semantic latency palette in member health strips.

FORM: Pinned by "优化一下UI，现代一点 参考stash", the explicit menu-only scope, and the added runtime-rules tab. The user chose dashboard, node cards/latency, overall finish and menu-bar experience; no further aesthetic interview is needed.

FINISH: Build both configurations, verify rendered light/dark states and navigation, perform finish review, and keep DESIGN.md plus .impeccable/design.json current. Synthetic review data must be labelled; local screenshots are ignored by git and are not shipping raster assets.

## Rules extension: rule providers

The request 「规则页面增加管理规则集的功能」 extends the existing Operate surface without changing its visual system. Rules keeps its existing toolbar and adds a visible 「规则集」 action. The in-panel list places 返回 / 规则集 / 添加 above a compact count, refresh and 更新全部 toolbar; provider cards show name, source, behavior, format, actual runtime count and last-update time. Cards occupy the full list width without trailing download buttons; individual HTTP updates stay in the context menu, and 更新全部 remains in the toolbar. Add/edit forms reuse PanelSection and PanelRow for HTTP, file and inline sources. HTTP forms omit the cache-path field (existing HTTP paths remain preserved); file sources retain their required file-path field. Last-update age reads 刚刚 below one minute, then a single whole-minute, whole-hour or whole-day value, refreshed at minute cadence without seconds. Names are read-only when editing; deletion requires confirmation and never removes files or RULE-SET references. RULE-SET rule creation offers configured providers in a native picker. Creating a provider also offers a 190 pt target-policy picker (default DIRECT), including configured strategy groups when the core is stopped. The provider definition and a matching RULE-SET reference at the beginning of rules are validated and saved as one transaction; editing a provider does not alter existing references.

Definitions always come from the selected YAML. Stopped cores still permit configuration editing. Pending restart hides stale counts and disables HTTP updates; saves use the existing strict validation and deferred-restart status badge. HTTP updates touch only running rule-provider content, never YAML, nodes or core lifecycle. Loading, empty, read-error, validation-error and disabled states remain explicit. Rule-type labels in the Rules list use 4 pt continuous corners instead of capsules; tags on other surfaces keep their existing capsule shape. This local extension otherwise inherits the fixed 360×560 pt layout, native typography, adaptive tokens, shared borders and reduced-motion-aware press/hover feedback; DESIGN.md and its token sidecar remain unchanged.

## Strategy extension: sampled request logs

The request 「顶部的代理tab改成策略，策略页面增加一个请求日志，可以查看请求走的那个策略」 changes the visible tab title to 策略 while retaining its identifier and existing group operations. A visible 请求日志 toolbar action opens an in-panel list with search, a bounded record count and a local-only clear action. Compact cards prioritize the destination, actual matched policy and final outbound, with observed activity, start time and matched rule. Details prioritize the target, complete policy-to-outbound chain and matched rule before connection metadata and sampling times. Forms, cards, headers, native text fields, small tags and press/hover feedback inherit the incumbent visual system.

History comes only from the core's one-second connection snapshots, keeps the newest 500 observed connections in memory and retains ended records. It never infers an old request's route from the currently selected group/node. Sampling limits remain documented in README.md rather than in a persistent explanatory paragraph above the list. Clear leaves actual connections untouched and suppresses re-adding existing active IDs; restart/profile change resets history. Waiting, empty, search-empty, stopped and reconnect/error states remain explicit, and activity is unconfirmed while sampling is interrupted. No new window, visual identity, chart or persistent browsing-history file is introduced. Verify actual routing through an isolated local core, completed retention, search/clear, and both macOS appearances before shipping.
